# Native actor identity retention in the controlled checkpoint

Classification: **STATIC AUDIT, NOT a native checkpoint acceptance test**. No game was launched, live process memory read, save modified, or bridge code changed by this follow-up. This audit uses the same pinned executable/SDK as `native-persistence-audit.md`.

**Recommendation:** retain the implemented exact native `mID` match for A/B animals and their native herds, additionally checking noun class, unique candidate, species/archetype and actual herd membership. Reject missing/mismatched nouns without spawning a replacement. Native serialization directly contains `mID`; there is no evidence here that a replacement key or enabling B's herd is needed. Fresh native reload still must establish which loaded nouns survive scene activation and accept original actions.

## Direct supporting evidence

1. Original `0xB21170` is a class census, not a persistence filter. It traverses manager `mNouns` at `+0x78` and `mObjects` at `+0x10C`, calls noun vtable slot `+0x20` (`GetNounID`), and counts entries by class. It has no `mbEnabled` test and does not classify by `mID`. `0xB21A20` compares those class-count maps against the saved header and formats class/count mismatch messages. Local exports: `m04-completion-id-retention/B21170.c.txt`, `m04-completion-noun-index/B21A20.c.txt`.

2. The actual manager strategy serializer is at vtable `0x145EE30`, `Write +0x28 -> 0xB201D0`, `Read +0x2C -> 0xB1FBD0`, `OnLoad +0x30 -> 0xB24240`. Constructor `0xB23290` installs that strategy table on the `+4` subobject. Consequently its decompiled offsets are four bytes below primary-object offsets. `Write` writes the count and every `mNouns` object reference through the stream's `WritePointer`; no enabled/disabled filter appears. `Read` reads each object as cGameData and inserts it into the intrusive noun list. Local exports: `m04-completion-noun-ctor/B23290.c.txt` and all files in `m04-completion-noun-streams/`.

3. Base noun `0xB184D0`/`0xB18540` call ClassSerializer Write/Read using native descriptor array `0x1567E48`. Original static initializer `0x13194A0` writes five descriptors. The fifth, at `0x1567F38`, is named **`mID`**, has attribute ID **`0x03CDD54B`**, primary-object offset **`+0x24`**, and the same uint read/write handlers used for `mPoliticalID`. The preceding fields are `mpGameDataOwner`, `mIsDestroyed`, `mPoliticalID` and `mDefinitionID`. The descriptor array is initially zero in the executable data and is populated by this native initializer; static raw zero bytes are not evidence of an absent runtime field. Local exports: `m04-completion-id-table/13194A0.c.txt` and `m04-completion-id-retention/B184D0.c.txt`, `B18540.c.txt`. Pinned SDK reference: `Spore/Simulator/Serialization.h` defines the 0x3C-byte Attribute and its read/write/offset members; `cGameData.h` places `mID` at +0x24.

4. Original manager descriptor initialization `0x131AD80` also registers **`cGameData::sInstanceIDGenerator`**, attribute ID **`0x03CDD5C7`**, global **`0x167BE28`**. The manager's binary schema uses `0x15685A8`; the XML-oriented adjacent schema starts at `0x1568788`. The exported `0x131AD80` explicitly demonstrates the same global counter descriptor for that adjacent schema. Exact counter restoration through the binary schema should be qualified with the native run; mID itself is already explicitly shared by binary base noun Read/Write. Local export: `m04-completion-id-table/131AD80.c.txt`; disassembly `0x131AD00..0x131AD6B` shows the binary schema's counter descriptor at `0x1568710`.

5. The original herd factory `0xB1EE70` constructs a 0x220-byte cHerd through `0xC6C2B0`, installing vtable `0x1471B90`. Its `Write +0x10 -> 0xC6C900` calls base cGameData Write, removes destroyed member references, updates the species key from the live profile, then calls ClassSerializer with herd schema `0x1577BC8`. Its `Read +0x14 -> 0xC69FF0` reads base cGameData and the same herd schema. Neither helper branches on `mbEnabled`. Assembly `0x134DC5C..0x134DCBE` registers **`mbEnabled`**, attribute **`0xD2AE8FDC`**, offset **`+0x218`**, descriptor at **`0x157812C`** inside that schema. A false enabled flag is therefore data to serialize, not a reason found here to drop the herd. Local exports: `m04-completion-herd-write/B1EE70.c.txt`, `m04-completion-herd-ctor/C6C2B0.c.txt`, and `m04-completion-herd-streams/C6C900.c.txt`, `C69FF0.c.txt`.

6. Stream `WritePointer 0x69D980 -> COMSerializer::Write 0x6A05F0 -> onSetSPSerializable 0x6A0110` registers referenced native objects and noun types; this path has no herd-enabled condition. `SaveClassObjects 0x69FB90` invokes each registered object's original virtual Write and accounts for failure. Internal serialized pointer-map keys are separate from the actual cGameData `mID` attribute and must not be treated as stable pointers across processes. Local exports are under `m04-completion-id-stream/`.

## Native post-load exception and remaining gate

**Secondary cPlayer objects are intentionally removed by the original game.** Manager `OnLoad 0xB24240` enumerates noun ID `0x02C21781` and calls native DestroyInstance for every player that is not the manager's primary player. This directly limits persistence of the M03 secondary reward context. The two controlled animal/herd IDs can still be restored independently, but the M04 sidecar must not claim a secondary cPlayer/reward-context restore from these results. Qualification of durable independent player progression remains its own capability.

`OnLoad` also clears/rebuilds manager maps and emits original phase messages. These can initiate type-specific activation or cleanup. This audit has not established that every live native noun survives every later callback. The next acceptance experiment must compare captured animal/herd IDs with the actual reloaded census, preserve mismatch evidence, and verify original actions after rebinding. It must not enable, respawn or rename B to hide a missing noun.

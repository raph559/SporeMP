## Bounded native sequence

1. **Freeze and prepare.** Record the exact source/artifact/environment manifest and personal/disposable baselines. Reserve a fresh evidence directory. Select one common NPC and one original contestable resource by stable global ID/generation, and record their native fingerprints. Choose the native reward observation and the respawn/reset path in advance. Complete the affected HOST/ABI/schema/negative tests before launching games.
2. **Start once and establish readiness.** Start the private coordinator, then the three explicit isolated original processes. Load the matching living fixture. Require native baseline application, ownership mapping and native readback from all roles. Start bounded exact-PID WGC captures; inspect a first frame to ensure they capture the correct original windows. Snapshot live generations and the initial state.
3. **Run the shared fight.** Client 1 and client 2 each submit original move/target/attack intentions against the same NPC. Exercise native response against each player under the declared G02 trial design without directly assigning health, death or reward. Stop action issuance once the observed target becomes terminal. Wait only for the recorded bounded original outcome window; an unknown timed-out mutation is not automatically retried.
4. **Contest the resource.** Release both authenticated requests from one harness barrier while the authority observes the same resource as available. Record each connection/request, authority arrival order and any queued native operations. Wait for one actual native grant/consumption and both resolved outcomes. If the first operation finishes before the second is in flight, report the attempt as inconclusive for contention and preserve it; a deliberate later duplicate challenge is a separate check.
5. **Compare and reconnect.** Take a terminal shared-state barrier before resetting the scene. Close/disconnect exactly one client, observe its original connection/process end, and reconnect with its prior private player credential. Verify G05 after a complete fresh native baseline, while retaining the worker and other client. Challenge the dead/consumed target again as an authorized late request and require no additional reward or resurrection.
6. **Exercise lifecycle.** Execute the chosen original respawn/reset path and one post-transition action. Native owner-1 death/respawn is the smallest focused reproduction of the known M06 avatar failure; if not covered by the selected reset, retain it explicitly as an unsupported capability instead of claiming general player respawn support. Reject stale pre-transition commands/baselines by the appropriate engine-independent and native generation checks.
7. **Repeat under impairment with the unauthorized challenge.** Use a fresh original encounter/resource after the explicit native reset or a new preserved fixture run. Repeat G01–G06 with impairment active; inject G08 while the ordinary clients remain in the encounter. Archive the exact impairment log with the real process/network evidence. Report each repeat separately before combining acceptance.
8. **Close and decide.** Stop only owned test processes through the implemented controls, await original exits, finish recorders, archive final traces and hashes, and restore test ACLs. Compare closed files to the corresponding baseline. An acceptance document evaluates every G01–G09 gate against exact evidence paths and records remaining stage/campaign limits. The harness retains `milestone_acceptance: NOT_VERIFIED` even when all its selected numerical checks pass.

Set a finite deadline for each native action/outcome and for the whole run before starting. Deadlines are failure bounds, not fabricated gameplay timing expectations. Unrelated keyboard actions must not overlap attributed IPC requests. If a required native event, identity, projection or capture fails, preserve the failed attempt, stop its dependent sequence and formulate the next smallest experiment; avoid an open-ended fight or repeated manual gameplay merely to repair capture.

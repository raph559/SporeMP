# M06 original-game network and scene acceptance

Status: **IN_PROGRESS** until the encompassing native evidence receives a separate acceptance decision. Host compilation, protocol fixtures, queued commands, the launcher preview and analyzer exit codes do not grant native acceptance. Preserve the complete M00–M20 plan in [MILESTONES.md](../../MILESTONES.md).

The original M06 acceptance is: two real client game processes join one original-game worker, load a consistent fixture, and observe distinct controlled actors. Out-of-order motion cannot resurrect an entity or change scene ownership. Unsupported versions fail clearly. Malformed/oversized messages are rejected. A reconnect obtains a fresh authoritative baseline without duplicating a player.

## Repeatable non-launching harness

The script `tools/native/m06-harness.py` only operates already-running, generation-bound private IPC or reads existing logs. It reserves fresh output directories and never retries a mutation with an uncertain result. Every report retains `milestone_acceptance: NOT_VERIFIED`.

```powershell
python tools/native/m06-harness.py self-test
python evidence/2026-09-14-m06-network/analyze-native.py --self-test

python tools/native/m06-harness.py snapshot --bridge-version 0.0.30 --coordinator-run local/m06-network/SERVER_RUN --output evidence/2026-09-14-m06-network/BEFORE_JOIN_SNAPSHOT

python tools/native/m06-harness.py actions --bridge-version 0.0.30 --clients 02 03 --seconds 12 --move-distance 0.5 --coordinator-run local/m06-network/SERVER_RUN --output evidence/2026-09-14-m06-network/CLIENT_ACTIONS
```

Replace uppercase path placeholders with actual fresh run names. `--bridge-version` must equal the frozen native build in those processes, rather than whichever artifact was rebuilt later. `--coordinator-run` accepts either the actual private coordinator directory or its server wrapper root; only the literal `coordinator.jsonl` or `private/coordinator.jsonl` is archived. No sibling invitation/config is copied.

Snapshot/archive captures bounded complete JSONL prefixes from each actor, bridge and NativeHost log, worker status and nonsecret network status, with exact byte counts and SHA-256. Actor logs are limited to 34 MiB each and coordinator logs to 256 MiB; exceeding the budget is a visible failure. The actor trace integrity check distinguishes a running prefix from a healthy final `trace_stop`. Public payload identities are hashed separately. No raw session config is copied or printed.

Actions requires all three connected roles and actual native pose samples before sending a command. It sends one move and then one jump from each selected client through WorkerControl; the client forwards its authenticated network intention to the dedicated original worker. It records:

- Client private IPC request and exit, followed by that client's unique new `network_intention` with expected player, remote entity and verb.
- Dedicated worker `network_native_intention` and `worker_command_queued`, correlated by request and owner. An accepted reply still means queued.
- One matching original `native_walk_request` plus actual same-entity native displacement of at least the chosen exercise distance; or original `native_jump_return` with accepted true and the matching later `native_landing`.
- Unchanged client/authority scene-exit counts during each action. Initial and final log prefixes remain available for independent analysis even if an action times out.

The default 0.5-unit movement threshold exists to establish a substantive exercise; it is not a visual-quality metric or a claim that movement obeys every original ability/state. Network action requests, native entries and landings are distinguished explicitly. No camera or keyboard input is generated by this harness. Overlapping unrelated client inputs make attribution ambiguous and fail the bounded action check.

## Native scene, motion and lifecycle checks

Dense original `network_authority_pose` events record each published owned entity's exact source tick, generation, position, orientation and velocity at the configured publication cadence. `scene_native_authority_sample` records actual original state, including owner/native-avatar identity. `scene_native_replica_sample` rereads actual native replica pose and records the remote source tick. A sample is not a native memory dump or a synthetic network fixture.

For every client sample, match the exact authority entity/generation/tick. Its actual native position must lie on the previous-to-target source segment; its normalized quaternion must lie on the corresponding shortest interpolation arc, allowing sign-equivalent quaternions; velocity must match the target snapshot. The analyzer reports explicit small float-rounding tolerances and maximum observed errors. Actor `qpc` values are relative to different process-local starts: never subtract them across processes or infer network latency or connected overlap from them. Exact common authoritative source ticks remain valid correspondence keys. Missing source ticks, backwards ticks, crossed owners, extra local-avatar assignments and off-segment values remain failures. Source snapshots that stop before the client trace also remain incomplete; they are not silently discarded.

Inspect exact-process WGC frames showing the two real original clients, the same visible fixture and two distinguishable controlled original actors. Review motion, camera, selection, animation and continuing native world presentation. Numerical agreement or a screenshot container alone does not establish that experience. Normal Play's retained M05 Off boundary remains separate from the multiplayer slice; do not relabel a prior build's Off test as a new M06 regression run.

Reliable spawn/despawn, entity-generation and scene-owner fences require protocol tests with deliberate malformed, oversized, incompatible, duplicate, stale and reordered inputs. Native actor traces verify observed identities/lifecycle; absence of bad native values does not establish that a negative packet challenge actually ran. Use the real network HOST/TLS tests and record their exact source/version, inputs and exits separately:

```powershell
ctest --test-dir build/win32 -C Release -R network_host --output-on-failure -V
```

HOST queue/parser/session/TLS checks remain labeled HOST/FIXTURE even when their sockets and Schannel handshake are real. Unexercised native dynamic NPC creation/removal, ability states, death/respawn, shared encounters, inventories and campaign progression remain visible prerequisites for their corresponding later features, rather than being inferred from pose replication.

## Disconnect, fresh baseline and clean closure

Root/operator explicitly closes or disconnects one selected client and records the actual original process/connection end. The authority and other client must continue with unchanged source scene/player identities. Reconnect using the same private player credential, with a fresh client process or the implemented same-process reconnect path. Require a fresh strictly higher coordinator baseline, one native application of that baseline, the same authenticated player/global entity generation and exactly one controlled native avatar. A reconnect must not create another player-owned entity or reset another client's scene.

Archive the old generations before their metadata is replaced; recapture their final logs later using the frozen source descriptors:

```powershell
python tools/native/m06-harness.py archive --bridge-version 0.0.30 --from-snapshot evidence/2026-09-14-m06-network/CLIENT_ACTIONS/report.json --coordinator-run local/m06-network/SERVER_RUN --output evidence/2026-09-14-m06-network/CLOSED_OLD_GENERATIONS

python tools/native/m06-harness.py snapshot --bridge-version 0.0.30 --coordinator-run local/m06-network/SERVER_RUN --output evidence/2026-09-14-m06-network/AFTER_RECONNECT

python evidence/2026-09-14-m06-network/analyze-native.py evidence/2026-09-14-m06-network/CLOSED_OLD_GENERATIONS/report.json evidence/2026-09-14-m06-network/CLIENT_ACTIONS/report.json evidence/2026-09-14-m06-network/AFTER_RECONNECT/report.json --output evidence/2026-09-14-m06-network/NATIVE_ANALYSIS.json
```

The analyzer validates archive hashes and overlapping prefixes, expected local-avatar ownership, exact source/interpolation matches, native action chains, distinct reconnect baselines and original closed lifecycles. Claimed action events must equal the archived native rows; displacement is recomputed. Three-process presence requires a recorded OS enumeration or the actions harness's generation-bound live status replies and connected before/after snapshots, backed by all three exact processes' `created_suspended`/`game_exited` NativeHost UTC records. Those timestamps bound process lifetimes; they do not measure network latency or native ready duration. Missing evidence remains NOT RUN. Reconnect ordering uses the shared authoritative source tick rather than client-relative QPC.

Spawn, removal or application errors remain material even if the process subsequently exits cleanly. A controlled native death leaves the qualified living fixture and is recorded explicitly; a successful earlier movement prefix does not prove death/respawn parity. The analyzer never grants the milestone; required visual/negative/isolation gates remain explicit. Exit 0 means the implemented selected trace checks have no failure, not that NOT RUN gates have passed. Exit 1 means a selected numerical, lifecycle or provenance check failed. Corrupt input fails before producing a success report.

After explicit shutdown, require game/host exits 0, healthy actor detach, intact bridge initialize/dispose lifecycle and bounded log health. Finish owned recorders before inspecting closed files. Verify personal hashes and disposable save trees against their corresponding baselines, while distinguishing normal cache/config changes from actual persistent world changes. Root records which operations were observed and any unavailable prerequisites in the final [M06 session](../../evidence/2026-09-14-m06-network/SESSION.md), followed by a separate acceptance decision against the original clauses.

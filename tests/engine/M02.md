## Reusable paired native procedure

1. Prepare a fresh Creature campaign in the disposable account with a normal controllable native avatar. Record how it was obtained and the game/content/creature identity. A launcher opening to the main menu is not a gameplay fixture. Exit normally, then snapshot/hash the closed disposable profile for this test pair; no copying of a live profile.
2. Reference run, new unique run name:
   `pwsh -NoProfile -File tools/native/invoke-isolated.ps1 -Action Launch -RunName m02-reference-01 -Configuration Release -ObservationMode Off`
   Use the normal game's jump control, allow a full landing, move around long enough for native NPC activity, then leave/reload the scene and exit normally. Record video and observed behavior. The reference clears any inherited M02 environment switch and installs no new observation hooks.
3. With the game closed, restore only the disposable fixture to exactly the recorded starting state. Confirm hashes. Do not restore the user's personal profile. Randomness is uncontrolled unless separately demonstrated; compare native invariants rather than requiring identical AI animation/timing.
4. Observed run, new unique run name:
   `pwsh -NoProfile -File tools/native/invoke-isolated.ps1 -Action Launch -RunName m02-observed-01 -Configuration Release -ObservationMode Observe`
   Repeat the same input sequence. In the normal cheat console, `sporemp_trace` (no arguments) prints probe counters and flushes observations. It does not trigger a native gameplay action or write saves. Record accepted and rejected jumps where ordinary controls produce them, full landing, avatar/NPC AI intervals, at least one actual entity destruction and a scene exit/reload. Do not force damage or manufacture a destroyed object solely by setting fields.
5. Close normally. Check guard success/payload identity, exactly one matching bridge initialization/disposal, game exit 0, personal-file hashes unchanged, and gameplay trace footer. Analyze the actual recorded trace with:
   `python tools/native/analyze-gameplay-trace.py PATH_TO_GAMEPLAY_JSONL --require-m02-coverage --output FRESH_REPORT_JSON`
6. Compare reference/observed video and game outcomes: exactly one native result per invocation, matching jump/landing behavior, no duplicated resource change/reward, normal AI, clean scene transitions and appropriate object invalidation. Record diagnostic overhead using measured frame durations and trace sizes. One later landing on the same entity is temporal association only; it needs the native sequence/video and binding audit to establish the action's meaning.

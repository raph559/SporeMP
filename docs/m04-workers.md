## Implemented process boundary

`src/worker` has no game SDK dependency. The guarded `SporeMP.NativeHost.exe` owns one original `SporeApp.exe` through a Windows job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. It verifies executable, content, loader and bridge hashes, actual standard-account SID, shell-folder paths and denied personal/game/peer write access before starting a suspended child. An actual-SID global mutex and process-token enumeration reject a second game in the same profile before injection. An unqueryable process identity fails closed.

The worker is detached from the short-lived launcher/backend process. Closing an operator pipe does not shut down the worker; the native action probe repeatedly closes its real control process while original AI continues. Losing the supervisor ends its contained child (HOST evidence); the retained native crash test leaves its peer healthy and accepting actions. In the new run, actual launcher closure and normal-account player process exit both precede further valid native A/B actions by the recovered worker. This establishes local process-lifetime independence; network clients and reconnects are later milestones. The launcher polls only while Settings is open and uses actual process identity plus private IPC; an old JSON file is not sufficient to report live readiness.

Bridge IPC begins through the pinned SDK post-init callback after the actor harness. One unmanaged `App::kMsgAppUpdate` listener handles at most one request per update, only with room for its reply. It invokes the existing M03 action queue on the verified engine thread. Disposal removes that listener and closes IPC before actor teardown. DllMain registers callbacks only. No network thread invokes native gameplay and no new gameplay implementation replaces the original functions.

## Private IPC version 1

Local message-mode Windows named pipes use overlapped I/O, one bounded input/output slot, a single server instance and `PIPE_REJECT_REMOTE_CLIENTS`. The engine pipe admits its worker SID and SYSTEM and checks the connected original game's PID. The operator pipe additionally admits elevated administrators without create-instance rights. Every client verifies the server PID through Windows. Generation names are fresh, nonzero 128-bit identifiers, not secrets or a future Internet authentication scheme.

| Byte offset | Wire value |
|---|---|
| 0 | `SMW4` magic, 4 bytes |
| 4 | Version 1, unsigned 16-bit |
| 6 | Exact frame size 128, unsigned 16-bit |
| 8 / 12 | Kind / operation, unsigned 32-bit each |
| 16 | Worker generation, 16 raw bytes |
| 32 / 40 | Sequence / scene epoch, unsigned 64-bit each |
| 48 | Ten unsigned 64-bit scalar values |

Integer encoding is explicitly little endian. No C++ struct dump, pointer, native container or arbitrary text command crosses IPC. Unknown sizes, schema, kinds, operations, zero generations and noncontiguous engine sequences are refused. An operator connection carries one request/reply; the supervisor assigns the contiguous engine request sequence. A reply must match that sequence and operation. A disconnected request cannot be delivered to a later controller connection. Mutation timeouts report an unknown outcome and are never retried automatically.

Implemented operations are `status`, `setup`, `players`, `rewards`, `jump`, `move`, `duel`, `retire`, `shutdown`, `stop`, `load`, `save`, `checkpoint` and `restore`. Bridge 0.0.14 load, pre-save checkpoint capture, save and restore have original-game evidence for the controlled fixture. Gameplay retains the existing Creature fixture, ownership and epoch gates. Load/save accept only zero scalar arguments and fixed `Satiria.spo`; persistence blocks other mutations while pending. Restore packs two six-word fingerprints into command scalar slots 0–5, low word first, with slots 6–9 zero. Status/reply slots 8/9 expose the persistence request/state; state 3 means native save returned true, not durable completion. Setup/player/reward/duel and persistence acceptance mean a pending request; action acceptance means queued, not applied or durable. The native action probe independently correlates original `DoJump` return with a later landing.

Status values are phase, app-update count, original NPC/avatar AI-entry count, A/B diagnostic IDs and original mode. `ready` requires a loaded original Creature avatar, fresh app messages and increasing native AI entries. It does not certify full scene correctness, global authority or persistence. App heartbeats run every 250 ms; status files publish every second. Three seconds without progress shows unresponsive/stalled; initialization is bounded to 120 seconds, absent engine updates to 30 seconds, command acknowledgement/native shutdown to 15 seconds. All failure kills are confined to the owned job and retain logs. `stopped_forced` is distinct from a clean native exit and never implies a checkpoint.

Keep its window unminimized: minimizing pauses native updates, and a 30-second update timeout stops the owned job. Startup/status/Stop use the real supervisor. Closing the launcher preserves the independently supervised worker, including bounded completion of a submitted backend mutation.

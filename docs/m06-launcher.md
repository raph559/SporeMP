# M06 launcher Join and Rejoin

Launcher **0.1.9** adds a private multiplayer card to Home. Play SPORE retains its normal Windows account and existing-save behavior. A complete host invitation enables Join only when the installation and compiled multiplayer components are available. The invitation is masked, held in launcher memory, and reused by Rejoin until the launcher closes. A changed invitation is a new Join.

The invitation format is `sporemp://join?host=HOST&port=PORT&cert=SHA256&token=TOKEN`. Both certificate pin and per-player token contain 64 hexadecimal characters. Parsing rejects duplicate/unknown fields, fragments, invalid host/port, all-zero credentials, control characters and oversized input. Errors never reflect the invitation. Invites identify the server certificate and player slot; they are private, not public server addresses.

The C# frontend sends the invitation over its private child stdin pipe, never a command argument or environment variable. The Python backend validates the installation, stages the guarded native payload, and creates a temporary configuration with a protected Windows DACL granting only its owner access. It writes this DACL when creating the file, before writing the credential. The configuration stays available through the native host lifetime and is removed by `finally` on success or an ordinary exception. An abrupt backend/OS termination can leave an owner-protected configuration file; it is not a saved launcher preference and is never included in report exports. Persistent encrypted invitations and packaged Internet hosting remain later work.

The line configuration is UTF-8 with a final newline and exactly these fields: `schema=1`, `host`, `port`, `certificate_sha256`, `credential`, `role=player`, `build_sha256`, `executable_sha256`, `content_sha256`, `fixture_sha256`. Build identity is the SHA-256 of the staged bridge DLL; executable identity is the pinned candidate executable hash; content identity is the SHA-256 of the raw candidate manifest file. Fixture identity is the SHA-256 of the current account's actual AppData `Spore/Games/Game0/Satiria.spo`, located through Windows shell folders. An absent fixture fails before connecting; a differing digest is rejected by the coordinator. No save is replaced or copied by Join. NativeHost independently validates these against its guarded payload/compiled identity and current-account fixture before native load. Arbitrary world/content transfer remains M08.

The backend first runs `SporeMP.Coordinator.exe --client-probe --config SESSION_PATH` with a 25-second process deadline. Exit 0 and JSON `authenticated:true` are required before any game process is launched. Unsupported build/content/protocol or rejected invitation returns the coordinator's bounded diagnostic to Settings. Then the backend invokes `SporeMP.NativeHost.exe --join GAME_ROOT PAYLOAD_DIR RUN_DIR SESSION_CONFIG`, with existing validated display arguments if configured.

The UI only displays Connected after the native bridge writes `network-status.json` with `state:"connected"`, player ID 1 or 2 and a positive baseline sequence. A successful preflight handshake alone does not produce Connected. The bridge owns the apply/ACK boundary. The launcher reads bounded atomic status snapshots and presents connecting, connected and disconnected states; technical connection details remain in Settings. Closing the launcher during Join hides the window and lets its existing native session finish. Duplicate Join requests and invitation edits are suppressed while a session is active.

For the dedicated-worker plus two-client native acceptance, developer worker enumeration also admits already-prepared profile 03. Existing generation/PID/SID/installation verification still applies. No account setup or developer profile control was added to the normal Play or Join card.

## Disposable-account acceptance staging

`tools/native/stage-m06-launcher.ps1` prepares the unchanged launcher for a developer test under the already qualified `SporeMP-M04-03` account. This is necessary on this test machine because the ordinary user's existing save has no `Satiria.spo`; the helper never copies a fixture or personal saves. It stages the launcher, existing Python runtime and current native payload in a fresh `C:\ProgramData\SporeMP\M04\03\launcher-tests\NAME` directory. The staged launcher still uses the same Home Join flow, installation checks and registered-process guard. Its settings and operation reports live in that stage's writable `local/launcher` directory.

Run `pwsh -NoProfile -File tools/native/stage-m06-launcher.ps1 -Mode Stage -StageName NAME` once from the developer administrator account. This can take several minutes because the existing Python runtime is copied and hashed. After starting the current dedicated worker and first client through the established developer procedure, run `pwsh -NoProfile -File tools/native/stage-m06-launcher.ps1 -Mode Refresh -ManifestPath STAGE\stage-manifest.json`. Refresh updates only the current public peer registration and native payload; it does not copy the runtime again or restart an already open WPF launcher. It requires both peer supervisors to be live and runs a read-only prerequisite probe under account 03. The probe requires both current game PIDs in the unchanged process guard, the expected actual Windows shell folders and fixture, inaccessible peer secrets, and successful launcher preparation. Exit 0 is prerequisite evidence, not native Join acceptance. Neither mode starts WPF or SPORE.

The helper records every changed ACL. It grants noninherited `ReadAttributes` on the exact peer account/run parent directories for the existing reparse guard, plus inherited read access on each exact current peer run so atomically replaced public status remains readable. Existing session configs and credential-like files have protected ACLs before that grant; the probe checks that account 03 cannot open them. It grants no write access to peer runs and does not expose the account credential files. After the native tests and launcher close, restore each generated `stage-refresh-*.json` manifest in reverse creation order, then `stage-manifest.json`, using `-Mode Restore -ManifestPath PATH`. This also handles a failed or repeated Refresh without losing the original ACL state. Retain the stage and reports as local evidence until the session's save/process postchecks are complete.

After closing each actual launcher game, `python tools/native/m06-launcher-evidence.py --stage STAGE --run join-FIRST --run join-SECOND --output FRESH_DIRECTORY` archives the explicitly named Join/Rejoin runs in order. Optional repeated `--image PATH` arguments index existing M06 UI captures by hash and actual image format. The tool copies only the exact native host/bridge/actor/status logs and matching completed backend result, checks pinned original-game identity, apply-before-connected order, the single owned native avatar, stable player/entity/generation with a newer Rejoin baseline, clean native exit and backend completion. It enumerates the private sessions directory only to confirm cleanup and never reads or copies its contents. Its report preserves any failed gate and requires separate manual visual acceptance; process-relative QPC is never used as a shared clock. If the authority is deliberately paused during a launcher lifecycle test, that test proves the launcher/baseline path only; movement acceptance must come from the separate active native run.

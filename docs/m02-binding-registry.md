## Hook transaction and lifecycle audit

`src/bridge/detour_transaction.cpp` uses the Detours include/library already pinned inside the SDK checkout. Its Win32 adapter is the same `__thiscall` original and `__fastcall(self, ignored_edx, ...)` shape documented in `Spore/CppRevEng.h`. Every attach/detach/error result is checked. A transaction enrolls the threads observed in a process snapshot and aborts the batch on failure. Thread creation during installation and removal remains a native qualification consideration; no thread-safe gameplay execution is assumed.

Unlike the upstream example's DllMain hook installation, this project installs/removes its seven hooks during the verified SDK post-init/dispose callbacks. DllMain still only registers those callbacks. The upstream core's unavoidable load-time binding work remains under the M01 host guard. No networking, engine calls, file I/O or joins were added to DllMain.

Hot hook records use fixed-size state and a bounded 64 KiB buffer. AI hooks count entries rather than writing per tick. Writes can still occur on the engine thread when the buffer fills or a frame sample flushes: the 2026-09-09 native pair measures presentation intervals and whole-process CPU. Medians are 16.55235/16.54640 ms Off/Observe and p99 17.9772/18.0072 ms; CPU differs by +0.01196 effective cores. The capped, one-minute samples and visible action comparison qualify this fixture, not a universal overhead bound. There is a 64 MiB trace cap with explicit overflow/footer diagnostics; an 8192-slot entity table refuses additional tracking at capacity. Both invalidate evidence coverage rather than silently counting dropped observations as complete.

The private entity table retains opaque address keys solely for lookup. It never dereferences them. IDs are monotonic across scene epochs, never persisted as player/species identities. Destroying objects cannot be re-observed until the native destroy returns. A callback on a foreign thread runs the original unchanged, skips state access and increments a visible counter. Such a trace cannot pass the M02 coverage gate. No save/artifact contents or native containers are written to this log.

Host/fixture evidence and the original source hashes live in `../evidence/2026-09-08-m02-observation/`. The first native trace and per-avatar/provenance analysis live in `../evidence/2026-09-08-m02-user-probe-01/`. All seven hooks were installed, observed and removed in that run with no recorded foreign callbacks/loss. That initial observation alone did not qualify baseline equivalence or overhead; the accepted paired evidence below supplies those checks for the recorded fixture.

## Accepted path and lifetime boundary — 2026-09-09

The unchanged typed x86 adapters were re-audited against the pinned SDK declarations. Each calls its original once with the same arguments/results. CreateInstance reads only the returned live object; DestroyInstance fences its token before forwarding and uses only the opaque key afterward. DoJump/OnJumpLand capture live state before forwarding, and never dereference a possibly invalidated receiver afterward. The entity table does not dereference stored keys. Scene exit clears all tokens while monotonic IDs continue. No gameplay mutation, networking, save call or persistent identity assignment is introduced.

Native evidence now covers 2,179 factory observations, 8,266 real destroy-entry invalidations, native avatar assignment, 499,571 NPC / 17,485 avatar AI entries, two Creature loads and one actual exit/reload. The avatar's native ID 232 recurs, but the mod token changes from 1104 / epoch 3 to 10467 / epoch 6. Strict analysis rejects later use of invalidated/stale tokens. This qualifies the paths actually encountered; it cannot prove all SDK factories/destructors, reentrant callbacks, foreign-thread behavior or other stages are safe. Host stress fixtures support capacity/reentrancy failure handling; no unobserved native path is promoted by them.

The paired videos show one visible original jump and landing per Space input, ordinary click-to-move and NPC activity, unchanged displayed health/DNA for the tested actions, and a functioning read-only console across reload. Reward/damage/resource-spending behavior was not exercised. Detailed measurements and exact trace sequences are in the completion evidence. The 2026-09-09 paired evidence is the current M02 acceptance decision.

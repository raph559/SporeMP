## Admission, identity and projection

Native calls run only on the captured engine thread. Network threads exchange bounded scalar messages. The authority performs a fresh noun census; species and archetype data must be available and the referenced live herd must be present in that census before admission. It captures native IDs, resource keys, owner, position, quaternion, velocity and vitals. Source IDs combine the scene epoch with the native noun ID and carry a tracked incarnation; destruction invalidates tracked identities before the original destructor runs. Session, scene, generation and baseline fences qualify these IDs. They are not persistent campaign identities.

A complete authenticated baseline reserves both player mappings before resolving NPCs. Each client's actual native avatar represents its own owner; its second local animal represents the other owner. No permanent global-avatar swap is required. Existing NPC adoption also checks species/archetype/herd identity. Missing animals require an existing matching native template; extra living animals are removed only after enumeration, avoiding native-list iterator invalidation. Partial failures quarantine the client instead of acknowledging a partial baseline.

All client mutation passes through `native_replica_project`; its explicit lifecycle scope admits only the required native creation/removal hooks. Pose projection calls the original spatial overrides and verifies native values afterward. Velocity uses the pinned SDK's scalar assignment, retaining original animation processing. Health is bounded by the original effective maximum. Only qualified owner-A stage DNA is projected; independent B progression is not inferred. Motion interpolation uses the preceding and target authoritative pose, normalizes the quaternion and respects generation/tombstone checks. Client intentions are routed to original worker movement/jump execution.

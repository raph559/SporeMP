## Normalized shared-state digest contract

A shared-state digest is useful only if it compares separately observed state. Hashing the same incoming packet three times would prove neither native application nor gameplay agreement. The M07 analyzer should construct one normalized projection from the worker's original native observations and one from each client's reread native projection. Keep the decoded canonical packet projection as an additional comparison so a native application defect can be distinguished from a transport defect.

Use explicit stable scalar identities and omit process-local addresses, local noun IDs, local clock origins, local-avatar flags, client-specific baseline numbers and interpolated presentation transforms. Record those omitted fields separately for ownership, provenance and pose checks. The same global actor is a different local avatar/noun in each client, and each client's baseline number is deliberately distinct.

The normalized terminal record needs these semantics; actual trace field names must be documented with the implementation:

| Field family | Required meaning |
|---|---|
| Scope | Versioned digest schema, authenticated session and authoritative scene/encounter identity. Record a common authoritative source revision/tick or an explicit settled-state barrier outside the canonical content. |
| Entity identity | Global entity ID/generation and owner, sorted deterministically. Include the exact NPC, both controlled actors and the contested resource relevant to the scenario. |
| Terminal state | Observed live/dead/removed state, terminal health, and the retained tombstone/resource-consumed generation. A missing local object must be corroborated by the authoritative terminal event and matching native removal/readback. |
| Reward | Native beneficiary player/species identity, reward category/value and absolute observed post-result state. Record the native result/event identity and command/resource correlation used to prove that repeated requests did not produce another outcome. |
| Projection provenance | References to the precise native trace sequences and network source revision used to derive every canonical row, retained outside the digest bytes. |

Encode deterministic, documented bytes before SHA-256: fixed schema and field ordering, sorted entity/result keys, explicit integer widths and UTF-8 only where a bounded string is required. If health/DNA are transmitted as float32, use the wire-width IEEE-754 value with a documented `-0` normalization; reject nonfinite values. A native reread discrepancy must be reported before any rounding or quantization. Do not silently round different terminal values to the same digest. Native-to-wire float conversion, if any, needs its own explicit numerical tolerance check and raw observed values.

Compare terminal discrete/reward state after the worker's outcome and client applications have reached a common revision or a recorded no-change barrier. Do not compare arbitrary wall-clock snapshots while native hunger, AI or movement continue; those represent different legitimate states. Do not freeze or disable native gameplay just to manufacture equal hashes. A sorted canonical record and a field-level diff must accompany every digest so a mismatch is reviewable. Digests supplement the original action/damage/death/award evidence; they do not establish its causality.

Host self-tests for the analyzer should demonstrate that changed health/death/reward/owner/generation/consumed state changes the comparison, that local noun IDs/baseline numbers do not, and that missing native provenance, duplicate JSON keys, broken archive hashes, NaN and stale source revisions fail. These tests exercise the evidence parser, not SPORE.

## Impairment scope and evidence

M07 requires a real native repeat with configured latency/loss. The exact M18 profiles remain the later release requirements: 100 ms RTT / 20 ms jitter / 1% loss, and 150 ms RTT / 30 ms jitter / 2% loss. Reusing the first profile for M07 is a practical choice, but do not claim a measured profile merely from its configuration values.

The current transport is TLS over TCP. Dropping arbitrary encrypted-stream bytes in a user-space TCP proxy corrupts TLS or the byte stream; it is not packet loss with normal TCP retransmission. A transparent delay-only proxy can test delay, but it cannot by itself satisfy packet-loss coverage. A drop rule applied to decoded application snapshots tests application-message omission, with different reliability semantics; label it accordingly and keep the actual network-loss gate open unless a documented test requirement explicitly chooses that model.

A valid packet-impairment run needs an existing suitable mechanism or a separately reviewed implementation scoped to the test endpoint/process traffic. Preserve TLS authentication and the original transport. Record where delay is introduced, whether the configured value is one-way or round-trip, jitter distribution/bounds, loss probability/direction, random seed when available, and actual counter/timing observations. Verify the challenge is active with the original processes connected. Reliable native lifecycle/reward state must converge despite retransmissions; measure queue pressure and action responsiveness without promising a threshold not present in the milestone.

Do not infer RTT or application delay by subtracting actor-trace `qpc` values from different processes: each trace has a different process-relative origin. Correlate request IDs and common source ticks for correctness. Measure elapsed request/response time on one clock, or introduce a documented host-QPC alignment mechanism with bounded uncertainty. A command script's own delay before submitting an action is not a network impairment.

The first M07 increment adds [a bounded byte-preserving delay/jitter relay](../tools/native/m07-delay-proxy.py), with [eight focused HOST tests](../tests/unit/test_m07_delay_proxy.py), including a real Schannel TLS authentication path. This is a TCP read-chunk delay mechanism, with no loss option and an explicit `packet_loss: NOT_IMPLEMENTED` report. It preserves byte order, applies backpressure, keeps payload/credential bytes out of logs and bounds runtime/connections/record count. Windows timer wakeups are checked against a high-resolution monotonic deadline before writing, and the report records actual requested/observed delays rather than inferring a network RTT. No original game has been run through it.

Read-only environment inspection found no installed WinDivert/clumsy path or driver. Existing WSL Ubuntu-24.04 has `tc`, `ip`, Python and namespace/veth support, but kernel `5.15.167.4-microsoft-standard-WSL2` explicitly lacks `CONFIG_NET_SCH_NETEM`; a dry-run `modprobe sch_netem` reports no module. Existing Downloads netem scripts also operate Linux loopback and broad shared mangle rules; they are not an appropriate tool for the current Windows process route. Exact commands/findings and helper test outcomes are preserved in [the impairment prerequisite record](../evidence/2026-09-21-m07-encounter/impairment-prerequisites.md). Real packet-loss acceptance requires an appropriate existing remote test environment or a separately reviewed tool/kernel change; it remains NOT RUN.

## Encounter harness and remaining work

The first implemented [M07 harness](../tools/native/m07-harness.py) provides `inspect`, `shared-combat`, `unauthorized-action` and `archive`. It reuses the bounded M06 process-generation, trace-provenance and archive checks, selects an explicit current NPC ID/generation, submits concurrent intentions through each real client and correlates original target assignment and paired native damage calls with an actual health decrease. Its state report compares sampled NPC health/death and published owner balances while checking controlled-avatar native DNA separately. This sampled digest is not a settled common-revision acceptance barrier. Native05/06 later exercised it and reported failed complete agreement, as recorded above. `full_m07` remains `NOT_VERIFIED` regardless of its operation exit code.

Further harness work must retain exclusive fresh output directories, bounded reads, duplicate-key/NaN rejection, exact bridge/executable/SDK provenance, immutable generation binding, actual status/process witnesses, archive prefix/hash checks and no automatic retry of uncertain mutations. It must not start a game, mutate saves, take desktop input, broaden credential ACLs or certify a milestone implicitly.

Implemented paths now cover current-census entity selection, distinct client-origin combat requests, sampled terminal-state comparison and an explicit negative network challenge. Remaining capabilities include a two-request pickup-contention barrier with actual authority-arrival evidence, settled common-revision native comparison, post-death reconnect comparison and impairment provenance attachment. Archive only nonsecret logs and public artifact hashes. A snapshot after a process respawn must not accidentally switch to a newer `current.json` generation when closing the older attempt.

For the unauthorized-action gate, the implemented developer-only challenge submits a jump for the currently observed foreign actor through client A's real authenticated connection. It requires a request-correlated coordinator ownership rejection received by that client, no matching forward or authority action in complete finite observation prefixes, and uninterrupted client B connectivity. A local IPC refusal cannot pass. The challenged client may enter its existing fail-closed state; both clients must be connected before submission. This path stays outside normal player controls and records no credentials. Its synthetic parser checks pass, while original-client acceptance remains NOT RUN.

The native implementation must identify a real original contestable pickup and its callable/action route before adding a pickup command to the harness. Two kill intentions and one DNA reward are useful combat evidence but are not the separate simultaneous-pickup requirement. Lack of a verified pickup entry keeps that gate NOT RUN and is a concrete next native research task; it does not authorize a replacement coordinator economy.

After the first changed death/baseline binding passes a bounded original test, combine only implemented paths into the complete two-run acceptance sequence. Do not launch a broad encounter soak while a known prerequisite remains absent. Full Creature hunger/inventory/progression, arbitrary content transfer and crash persistence remain their later milestones, with unsupported behavior visible in status and player-facing capability claims.
